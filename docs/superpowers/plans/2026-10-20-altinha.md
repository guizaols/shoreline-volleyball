# Altinha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new beach game, the altinha roda: 5 friends in a circle keep the ball up with named tricks, a shared roda score and individual FIFA Street style scores, tricks unlocked over time.

**Architecture:** Pure game logic in `lib/altinha.ts` (no DOM, stepped at 120 Hz like `lib/net.ts`), its save in `lib/altinha-progress.ts`, a Phaser scene `lib/altinha-scene.ts` that reuses the beach art and athletes, and a React page `app/altinha/` that reuses `TouchControls`. It does not go through `BeachMatch.tsx`/`beach-scene.ts`, which are already dense with three sports' branches.

**Tech Stack:** TypeScript, React (vinext/Next app dir), Phaser, `node --experimental-strip-types` tests with `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-10-20-altinha-design.md`

## Global Constraints

- Match the repo's style: dense one-line functions, short comments explaining *why*, Portuguese UI copy, English code names.
- Each task = one commit, with its test file added to `npm test` in `package.json`.
- No hidden dice for the human: whether a human touch works depends only on timing and distance, both shown on screen (timing meter, landing ring). Randomness is allowed only in CPU decisions.
- The live pass aim (which friend you'll pass to) is drawn on screen while you hold a direction.
- Works on desktop (keyboard) and phone (`TouchControls`).
- Round: 120 s. Touches per turn: 3 by default, mode 1 or 2 selectable.
- When the ball drops, the roda goes on: roda streak resets, the dropper's combo is halved.
- Starting tricks: embaixadinha, coxa, cabeça.
- Online is out of scope.

## Review Focus

- **Pause/blur mid-flight** (tab hidden while ball is in the air): the round must freeze and resume with the same ball, not drop it. → test in Task 1.
- **Pressing with no ball coming to you** (CPU's turn): the press must be ignored, not queue a touch that fires later on your next ball. → test in Task 1.
- **Mode 1 toque**: the first touch must always be a pass, even if you pressed J (keep-up). → test in Task 2.
- **Broken or tampered save** (`localStorage` JSON garbage, negative numbers, huge numbers): read as a fresh save. → test in Task 4.
- **Round ending while the ball is in the air**: score is final at 0 s; a touch after that does not add points. → test in Task 3.

### Task 1: Roda core — circle, ball, turns, drops, roda score, timer

**Files:**
- Create: `lib/altinha.ts`
- Create: `lib/altinha.test.ts`
- Modify: `package.json` (`test` script)

**Interfaces:**
- Consumes: `moveRunner`, `clamp` from `lib/net.ts`; `FLOOR`, `type Player` from `lib/game.ts`; `pressTiming`, `PERFECT_ETA` from `lib/arcade.ts`.
- Produces:
  - `type AltinhaInput={x:number;z:number;jump:boolean}`
  - `createAltinha(opts?:{maxTouches?:1|2|3;random?:()=>number})` → state with: `status:'ready'|'playing'|'paused'|'over'`, `resumeStatus`, `clock`, `timeLeft` (120), `players:Player[]` (5; index 0 is the human), `spots:{x:number;z:number}[]`, `ball:{x,z,y,vx,vz,vy}`, `receiver:number` (who the ball is going to), `holder:number`, `touchesThisTurn`, `maxTouches`, `rodaScore`, `rodaStreak`, `rodaBest`, `individual:number[]` (5), `combo:number[]` (5), `drops`, `charge`, `queued:null|{kind:'keep'|'pass';target:number;hold:boolean;eta:number}`, `feedback`, `feedbackTime`, `contactSerial`, `timing:number|null`, `random`.
  - `type Altinha=ReturnType<typeof createAltinha>`
  - `startAltinha(g)`: `ready`→`playing`, ball tossed up above the human.
  - `altinhaGuide(g)` → `{x:number;z:number;time:number;height:number}`: where/when the ball reaches contact height (for the landing ring and timing).
  - `pressAltinha(g)`: start holding (charge). Ignored unless `status==='playing'` and `receiver===0`.
  - `releaseAltinha(g,input:{x:number;z:number},kind:'keep'|'pass')`: queue the human touch; `eta=altinhaGuide(g).time` at release.
  - `passTarget(g,input:{x:number;z:number})` → friend index 1–4: the friend whose spot is closest in angle to the input direction from the human; neutral input → next friend clockwise.
  - `stepAltinha(g,dt:number,input:AltinhaInput,level:string)`
  - `pauseAltinha(g)`: toggles `playing`↔`paused` via `resumeStatus`.

Values (from the decisions; the builder may tune with the sim in Task 3 but must note any change):
- Circle centre `(500,225)`, radius `150`, 5 spots at angles `90° + i·72°` (human at the bottom, closest to camera).
- Contact: a queued touch fires when the falling ball reaches contact height and the receiver is within `45` units horizontally; otherwise `feedback='LONGE'` and the ball keeps falling.
- Ball reaching `FLOOR` with no touch = drop: `drops++`, `rodaStreak=0`, `combo[receiver]=Math.floor(combo[receiver]/2)`, `feedback='CAIU!'`, then after `1 s` the receiver tosses it up again (status stays `playing`).
- Each successful touch: `rodaStreak++`, `rodaScore+=5*(1+Math.floor(rodaStreak/10))`, `rodaBest=max`.
- Keep-up touch sends the ball up over the same player (flight ≈ `.8 s`); pass sends it to the target's spot (flight ≈ `1.1 s`). After `maxTouches` touches in a turn the next touch is forced to a pass.
- `timeLeft` counts down only while `playing`; at 0 → `status='over'`.

### Task 2: Tricks, individual score, combo, salvadas, touch modes

**Files:**

**Interfaces:**
- Consumes: Task 1 state and functions.
- Produces:

  - `trickFor(input:{x:number;z:number},hold:boolean,jump:boolean,unlocked:readonly TrickId[])` → `TrickId` (falls back to `embaixadinha` when the matching trick is locked)
  - State gains: `unlocked:TrickId[]` (option `unlocked` in `createAltinha`), `lastTricks:TrickId[][]` (per player, last 2), `style:number` (0–100, human), `perfects:number`, `saves:number`.

Trick table (decided; points/risk tunable with the sim, note changes):

| id | name on screen | dir | hold | jump | points | risk | contact height above floor | unlockAt (total individual score) |
|---|---|---|---|---|---|---|---|---|
| embaixadinha | EMBAIXADINHA | none | no | no | 10 | 0 | 60 | 0 |
| cabeca | CABEÇA | up | no | no | 15 | .05 | 150 | 0 |
| coxa | COXA | down | no | no | 15 | .05 | 85 | 0 |
| peito | PEITO | side | no | no | 20 | .08 | 115 | 300 |
| ombro | OMBRO | side | yes | no | 30 | .12 | 130 | 800 |
| letra | LETRA | down | yes | no | 50 | .2 | 55 | 1500 |
| volta | VOLTA AO MUNDO | none | yes | no | 70 | .28 | 65 | 2500 |
| carretilha | CARRETILHA | up | yes | no | 90 | .35 | 60 | 4000 |
| tesoura | TESOURA NO AR | any | any | yes | 120 | .4 | 170 | 6000 |

Rules:
- Risk is visible, not a dice roll: timing quality `q=pressTiming(eta)`-based in 0–1; a trick succeeds when `q>=.35+risk`; otherwise the ball goes off sideways by `(1-q)*120` units (the next touch may need a salvada) or, if `q<.15`, it drops.
- Individual points: `points × (1+.5×combo) × (perfect?1.5:1)`, rounded. Combo is updated before scoring the touch: +1 when the trick is not in the player's `lastTricks`; a repeated trick leaves it unchanged. Only a drop lowers it (Task 1 rule).
- Salvada: a touch fired with the ball below 35 units above floor after the player moved more than 120 units for it → `+40` individual, `saves++`, `feedback='SALVADA!'`.
- Feedback text: trick name, plus ` · PERFEITO` on perfect timing.
- Style: `+points/10` per human trick, capped at 100.
- Mode `maxTouches:1`: every touch is a pass, whatever `kind` was asked.

### Task 3: CPU friends, gamebreaker, balance sim

**Files:**
- Modify: `lib/altinha.ts`
- Modify: `lib/altinha.test.ts`

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces:
  - CPU turn logic inside `stepAltinha`: CPU runs to `altinhaGuide`, takes 1..`maxTouches` touches (chosen with `g.random`), picks tricks from all 9 weighted toward easy ones, then passes. CPU passes to the human with probability `.4`, else to a random other friend.
  - CPU success: fails (drops) with probability `base + .2×(incoming pass was bad) + risk`, `base` by `level`: `Chill .02`, `Club .04`, `Pro .06`. A bad human pass (`q<.35+risk`) is the "bad incoming".
  - `armGamebreaker(g)`: when `style>=100` and `playing`: `gamebreaker=6` s, `style=0`, `feedback='ALTINHA DE OURO'`. While `gamebreaker>0`: ball gravity ×`.6`, human points ×2.
  - `altinhaResult(g)` → `{rodaBest:number;rodaScore:number;individual:number[];king:number;perfects:number;saves:number;drops:number}` (`king` = index of highest individual).
